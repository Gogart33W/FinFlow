# FinFlow — фікси + тотальний UI/UX редизайн (промпти для агента)

Контекст для агента (встав, якщо працює в новому чаті):

> Проєкт: FinFlow, Android, Kotlin, Jetpack Compose, Material3, Room, MVVM.
> Поточний стан дизайну: `ui/theme/Theme.kt` і `Color.kt` — це НЕЗМІНЕНИЙ
> шаблон Android Studio (Purple80/PurpleGrey80/Pink80, дефолтна typography
> тільки з bodyLarge, dynamicColor=true). Іконка застосунку — теж дефолтний
> шаблонний вектор Android Studio. Валюта `₴` захардкожена як текстовий
> літерал в `String.format(..., "%.2f ₴", ...)` в MainScreen.kt,
> StatisticsScreen.kt, BudgetsScreen.kt, AccountsScreen.kt — це треба
> прибрати заодно з мовним перемикачем, інакше англійська локалізація
> буде показувати суми з гривнею. minSdk 24, targetSdk 36.

Давай ці промпти **по одному, не пачкою**. Останній раз агент проігнорував
цю пораду, зробив усі 8 промптів за раз і в результаті двоє з них
(бекап-імпорт, тест міграції) виявились технічно зламаними, хоч і виглядали
завершеними в комітах. Чим більший шматок роботи без паузи — тим більше
шансів отримати таку саму тиху поламку в дизайн-системі чи темі.

## Промпт 10 — Критичні фікси (зроби ПЕРШИМ, до дизайну)

```
Виправ три критичні проблеми в поточному коді:

1. BackupManager.importData() зараз вставляє категорії/рахунки/транзакції/
   бюджети зі старими id з файлу бекапу через OnConflictStrategy.REPLACE.
   Це небезпечно: дефолтні категорії/рахунок завжди мають однакові id (1-13,
   1) на кожному чистому інсталі, тож імпорт старого бекапу на пристрій з
   вже існуючими даними тихо перезатре локальні записи, чиї id випадково
   співпали. Перепиши імпорт так:
   - Для кожної категорії/рахунку з бекапу: insert БЕЗ id (Room згенерує
     новий автоінкрементний id), збережи мапінг oldId -> newId в Map<Long,Long>.
   - Для кожної транзакції/бюджету: перед insert підстав categoryId/
     accountId через відповідний мапінг на новий id, теж insert без id.
   - Обгорни весь імпорт в @Transaction (або db.withTransaction {}) —
     якщо щось впаде на середині, не має лишитись наполовину імпортованих
     даних.
   - Приберіть застарілий коментар в exportData() про budgets query — він
     уже вирішений, коментар просто забули видалити.

2. Додай превью перед імпортом: у SettingsScreen перед фактичним викликом
   importData спочатку розпарси файл (винеси парсинг з BackupManager в
   окремий публічний метод, що повертає BackupData?), покажи AlertDialog
   "Буде додано: N транзакцій, M категорій, K рахунків, L бюджетів" з
   кнопками Скасувати/Підтвердити, і тільки після підтвердження виконуй
   фактичний імпорт з мапінгом id з пункту 1.

3. Room migration test зараз не зможе запуститись: @Database має
   exportSchema = false і в build.gradle.kts немає room.schemaLocation.
   Онови app/build.gradle.kts:
   android {
       ...
       defaultConfig {
           ...
           kapt {
               arguments {
                   arg("room.schemaLocation", "$projectDir/schemas")
               }
           }
       }
   }
   (або блок kapt{} окремо на рівні модуля, дивлячись яка структура зручніша
   для поточної версії AGP). Постав exportSchema = true в @Database.
   Прожени ./gradlew assembleDebug щоб згенерувались json-файли схеми в
   app/schemas/, закоміть цю папку в git (вона потрібна для тестів
   міграції в CI/на будь-якій машині, це не generated-and-ignored файл).
```

```
Задача: побудувати повноцінну дизайн-систему замість шаблонних
Purple80/PurpleGrey80/Pink80 з Android Studio template. Це фінансовий
застосунок — палітра має викликати довіру і спокій, не "ще одна
фіолетова Material Design демо-апка".

1. ui/theme/Color.kt — повністю переписати. Концепція: глибокий
   smaragd/jade як primary (асоціація з грошима, але не токсично-зелений
   неон), теплий нейтральний фон замість чистого білого/чорного.

   Light scheme:
   - primary: #0F6B4F (глибокий smaragd)
   - onPrimary: #FFFFFF
   - primaryContainer: #B8F0D4
   - onPrimaryContainer: #002114
   - secondary: #4C6358 (приглушений сіро-зелений)
   - background: #FBFAF7 (теплий off-white, не #FFFFFF)
   - surface: #FBFAF7
   - surfaceVariant: #E8ECE6
   - onBackground / onSurface: #1A1C1A
   - error: #BA1A1A
   - outline: #6F7975

   Dark scheme:
   - primary: #8AD5B5 (світліший smaragd для контрасту на темному)
   - onPrimary: #00391F
   - primaryContainer: #00522F
   - onPrimaryContainer: #B8F0D4
   - background: #10130F (не чистий #000000 — теплий майже-чорний)
   - surface: #10130F
   - surfaceVariant: #1F2D25
   - onBackground / onSurface: #E1E3DD
   - error: #FFB4AB

   доменні кольори): income = #2E7D5B (light) / #6FCF9E (dark),
   expense = #C4553D (light) / #F2A088 (dark). Ці два винеси як
   окремі val-и (FinFlowExtendedColors), не намагайся підмінити ними
   стандартні tertiary/error — це різні речі семантично.

2. ui/theme/Type.kt — повна типографічна шкала, не тільки bodyLarge.
   Підключи шрифт через Google Fonts Downloadable Fonts API (не
   зашивай .ttf в assets, це збільшує apk) — родина "Manrope" для
   display/headline/title (геометричний, сучасний, добре виглядає на
   великих цифрах балансу) і "Inter" для body/label (краще читається
   в дрібному тексті). Заповни ВСІ рівні Typography: displayLarge/
   Medium/Small, headlineLarge/Medium/Small, titleLarge/Medium/Small,
   bodyLarge/Medium/Small, labelLarge/Medium/Small — не залишай
   дефолти Material3 для решти.

3. Створи ui/theme/Shape.kt: Shapes(extraSmall = 4dp, small = 8dp,
   medium = 12dp, large = 16dp, extraLarge = 28dp) — картки транзакцій
   і bottom sheets використовують large/extraLarge, чіпи і малі кнопки
   — small/medium. Зараз в проєкті corner radius розкидані по місцях
   де попало (перевір і уніфікуй всі RoundedCornerShape(...) виклики
   на ці токени).

4. Створи ui/theme/Spacing.kt: об'єкт з val-ами xs=4dp, s=8dp, m=16dp,
   l=24dp, xl=32dp — і заміни магічні числа padding/spacing по всіх
   екранах на ці токени (зараз всюди розкидані .padding(16.dp),
   .padding(12.dp), .padding(20.dp) без системи).

5. Theme.kt: онови FinFlowTheme щоб брав darkTheme не з
   isSystemInDarkTheme() напряму, а з нового ThemePreference (наступний
   промпт це додасть) — поки що просто зроби параметр themeMode:
   ThemeMode = ThemeMode.SYSTEM з можливістю форсувати LIGHT/DARK.
   dynamicColor онов на false за замовчуванням (Material You перекриє
   вашу продуману палітру динамічними кольорами шпалер користувача —
   це не те, що ти хочеш для fintech-бренду; краще дай це окремим
   тумблером "Дозволити кольори від шпалер" в Settings, вимкненим
   за замовчуванням).

Критерій приймання: жодного хардкод Color(0xFF...) чи .sp/.dp
магічного числа поза Color.kt/Type.kt/Shape.kt/Spacing.kt в UI-шарі
(окрім самих цих файлів-джерел істини).
```

```
Задача: користувач має обирати тему в Settings, а не тільки залежати
```

## Промпт 13 — Мова застосунку (незалежно від системної) + прибрати хардкод валюти

```
Задача: вибір мови застосунку (uk/en) через UI Settings, незалежно від
системної мови телефону, плюс закрити давній борг з хардкод-валютою.

1. Мова: використай androidx per-app language API
   (AppCompatDelegate.setApplicationLocales) — це стандартний сучасний
   підхід, працює на Android 13+ нативно через систему, і через
   AppCompat-бекпорт на старіших версіях без потреби вручну керувати
   Context/attachBaseContext. Додай залежність
   androidx.appcompat:appcompat:1.7.0 (перевір актуальну версію).
2. SettingsScreen: додай вибір мови (Українська/English) через
   SegmentedButton чи dropdown. При виборі виклич
   AppCompatDelegate.setApplicationLocales(LocaleListCompat.forLanguageTags("uk"))
   (або "en"). Система сама застосує ресурси, Activity перестворюється
   автоматично — це очікувана і коректна поведінка API, не баг.
3. Прибери res/xml locale config якщо конфліктує (перевір
   android:localeConfig в маніфесті, якщо додавав автоматично AGP —
   узгодь зі списком підтримуваних мов uk/en).
4. Валюта: створи res/values/strings.xml запис
   <string name="currency_symbol">₴</string> і res/values-en/strings.xml
   з тим самим (валюта не залежить від мови інтерфейсу, це окрема вісь
   — людина може читати English UI і мати гривню). Створи один спільний
   форматер (наприклад CurrencyFormatter.kt: fun formatAmount(amount:
   Double, currencySymbol: String): String) і заміни ВСІ 8+ місць з
   String.format(Locale.getDefault(), "%.2f ₴", ...) на виклик цього
   форматера, який бере символ з strings.xml через stringResource(), не
   хардкодить "₴" літералом. Це закладає фундамент під майбутню
   мультивалютність (Фаза 5 з попереднього роадмапу) — символ валюти
   стає налаштуванням, а не текстом в коді.

Критерій приймання: перемикання мови в Settings змінює весь UI-текст
без хардкод-гривні що плутається з англійською локаллю; вибір мови
незалежний від системної мови телефону і переживає перезапуск.
```

## Промпт 14 — Іконка застосунку (повний редизайн)

```
Задача: замінити шаблонну Android Studio іконку (градієнтний "листочок")
на власну adaptive icon, що відповідає новій дизайн-системі.

Дизайн-бриф:
- Концепція: не буквальна монетка/гаманець (це найбільш заїжджений
  штамп в категорії fintech — Monefy, Wallet, Spendee всі це вже мають).
  Натомість: стилізована висхідна лінія/графік (як силует зростання
  балансу) що плавно переходить у форму літери "F", вписана в м'яке
  скруглене поле. Мінімалістично, 2-3 кольори максимум.
- Кольори строго з нової дизайн-системи: фон adaptive icon —
  primaryContainer light (#B8F0D4) або суцільний primary (#0F6B4F),
  сама фігура — контрастний colorOnPrimary/onPrimaryContainer.
- Технічно: стандартна adaptive icon структура — окремо
  ic_launcher_background.xml (суцільний колір або дуже тонкий градієнт,
  без деталей що будуть обрізані маскою) і ic_launcher_foreground.xml
  (сам символ, вписаний в safe zone 66dp з 108dp viewBox — тобто
  символ не повинен виходити за центральні ~61% полотна, інакше
  обріжеться на пристроях з круглою/квадратною маскою).
- Згенеруй новий Vector Drawable (не растр) для foreground з чистою
  геометричною формою (Path з простими кривими/лініями, не намагайся
  імітувати растрову ілюстрацію в vector XML).
- Онови mipmap-anydpi-v26/ic_launcher.xml і ic_launcher_round.xml
  щоб посилались на нові background/foreground.
- Растрові mipmap-*/ic_launcher.webp можна лишити як fallback для
  API <26 — згенеруй їх з нового вектора через Android Studio Image
  Asset Studio (або еквівалентний інструмент), не вручну.

Важливо чесно про очікування: LLM-агент, що пише XML-код вектора,
не замінить професійного дизайнера у Figma для по-справжньому
"дорогого" бренд-знаку. Це дасть чистий, охайний, невеликий значок
що вже не виглядає як шаблон — але якщо після цього кроку іконка
все ще не подобається на вигляд, це той момент, де варто витратити
$30-50 на Fiverr на 2-3 варіанти від живого дизайнера, а не намагатись
виїхати ще одним промптом. Іконка — це перше враження в Google Play,
на ній не варто економити нескінченно на AI-ітераціях.

Критерій приймання: іконка не є шаблоном Android Studio, коректно
рендериться на круглій/квадратній/squircle масці (перевір хоча б в
Android Studio App Icon Preview), відповідає кольорам нової теми.
```

## Промпт 15 — Повний UI/UX прохід по всіх екранах

```
Задача: застосувати дизайн-систему з Промпту 11 до кожного існуючого
екрану і довести взаємодію до сучасного рівня. Це найбільший промпт —
якщо відчуєш що виходить занадто багато за раз, розбий сам на
під-кроки по екрану, але тримайся такого чек-листа для КОЖНОГО з:
MainScreen, AccountsScreen, StatisticsScreen, BudgetsScreen,
SettingsScreen, OnboardingScreen, PinAuthScreen, AddTransactionBottomSheet.

Загальний чек-лист на кожен екран:
1. Всі кольори/spacing/shape через токени з Промпту 11, жодних магічних
   чисел чи Color(0xFF...) в самому екрані.
2. Порожній стан (empty state): якщо список транзакцій/рахунків/бюджетів
   порожній — не показуй порожній LazyColumn, покажи ілюстрацію
   (простий vector, в стилі нової іконки) + текст-заохочення + кнопка
   дії ("Додай першу транзакцію"). Зараз, ймовірно, порожній екран просто
   білий/порожній список — перевір і виправ.
3. Стан завантаження: якщо є будь-який suspend-виклик з помітною
   затримкою (імпорт/експорт бекапу особливо) — показуй
   CircularProgressIndicator або skeleton, не заморожений UI без
   фідбеку. Для BackupManager операцій з Промпту 10 — обов'язково.
4. Insets/edge-to-edge: targetSdk 36 форсує edge-to-edge на Android 15+.
   Перевір КОЖЕН екран на WindowInsets.safeDrawing/systemBars — контент
   не повинен ховатись під статус-баром чи жестовою навігацією знизу.
   BottomNavigationBar особливо перевір — навігаційні жести знизу часто
   перекривають останній пункт списку без правильного contentPadding.
5. Motion: заміни різкі showBottomSheet/навігаційні переходи на
   стандартні Material3 переходи (AnimatedContent для перемикання
   вкладок/періодів статистики, spring-based анімація для
   SwipeToDismissBox який вже є в MainScreen). Баланс на MainScreen —
   додай легку анімацію лічильника при зміні суми (animateFloatAsState
   або власний counter-effect), це дає відчуття "живого" застосунку
   замість миттєвої підміни цифри.
6. Accessibility: contentDescription на всіх Icon (зараз, ймовірно,
   частина іконок категорій/навігації без опису), мінімум 48dp touch
   target на кожен клікабельний елемент (перевір FilterChip/IconButton
   розміри), контраст тексту на кастомних кольорах категорій (colorHex
   з CategoryEntity може дати нечитабельний текст на світлому/темному
   фоні — порахуй контраст і вибери onColor автоматично, не хардкодь
   завжди чорний/білий текст поверх довільного кольору категорії).
7. Типографічна ієрархія: великі суми (баланс, підсумки) — displayMedium/
   Large з новою типографікою, назви екранів — titleLarge, другорядний
   текст (дата, підпис категорії) — bodySmall/labelMedium. Перевір що
   ніде не використовується один і той самий bodyLarge для всього
   підряд (це, скоріш за все, поточна ситуація, бо Type.kt має тільки
   один заповнений рівень).

Порядок екранів (роби по одному, комітай окремо):
MainScreen → AddTransactionBottomSheet → AccountsScreen →
StatisticsScreen → BudgetsScreen → SettingsScreen → OnboardingScreen →
PinAuthScreen → BottomNavigationBar (фінальний прохід, коли всі
екрани вже в новому стилі — узгодь іконки/лейбли вкладок з рештою).
```

## Порядок віддачі промптів

**10 → 11 → 12 → 13 → 14 → 15**, і 15 — по одному екрану, не всі
скопом. Після кожного відкрий застосунок (світла/темна тема, обидві
мови) і подивись руками — дизайн-баги на відміну від логічних не ловляться
тестами, тільки очима.
